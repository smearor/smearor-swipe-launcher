# Message System

The message system is the communication backbone of the launcher. All plugins and services communicate through typed messages routed by the central message
broker.

## FfiEnvelope

Every message is wrapped in an `FfiEnvelope` — an ABI-safe envelope that carries a raw pointer to the payload:

```rust
pub struct FfiEnvelope {
    pub sender_id: String,
    pub target_instance_id: String,
    pub topic: String,
    pub type_id: u64,
    pub payload: *mut c_void,
    pub destroy_payload: Option<extern "C" fn(*mut c_void)>,
    pub clone_payload: Option<extern "C" fn(*mut c_void) -> *mut c_void>,
}
```

## Sending Messages

Use the `MessageBroadcaster` trait methods:

```rust
// Send a typed message to a topic
self.broadcast_message("service.audio.command", &AudioCommand { action: AudioAction::VolumeUp });

// Send to a specific instance
self.broadcast_message_to_instance("side2", "area.open", &AreaOpenMessage { area_id: "submenu" });

// Send a plain string (for generic widgets)
self.broadcast_string("area.open", r#"{"area_id":"submenu"}"#);
```

## Receiving Messages

Implement `MessageHandler<T>` for each message type your plugin handles:

```rust
impl MessageHandler<FfiEnvelopePayload<AudioStatus>> for MyWidget {
    fn handle_message(&self, message: FfiEnvelopePayload<AudioStatus>, _sender_id: &str) {
        let status = &*message;
        // Update UI based on status
    }
}
```

The host's `on_message` dispatch checks the `type_id` and calls the appropriate `handle_envelope_message`.

## TypedMessage Trait

Every message type implements `TypedMessage` which provides a stable `TYPE_ID`:

```rust
pub trait TypedMessage {
    const TYPE_ID: u64;
}
```

This `TYPE_ID` is generated by `generate_type_id("TypeName")` and is used by the broker to match envelopes to handlers.

## MessageTopic Trait

Message types can declare their topic via `MessageTopic`:

```rust
pub trait MessageTopic {
    fn topic() -> &'static str;
}
```

This allows using `broadcast_message_to_topic()` which derives the topic from the type.

## Topic Conventions

| Pattern                               | Direction             | Example                         |
|---------------------------------------|-----------------------|---------------------------------|
| `service.{id}.command`                | Widget → Service      | `service.audio.command`         |
| `service.{id}.status`                 | Service → All Widgets | `service.audio.status`          |
| `service.{id}.response.{correlation}` | Service → Widget      | `service.http.response.abc123`  |
| `area.{action}`                       | Widget → Instance     | `area.open`                     |
| `core.{action}`                       | Widget → Host         | `core.close`                    |
| `mcp.register.{type}`                 | Plugin → Registry     | `mcp.register.tool`             |
| `mcp.invoke.{type}`                   | Client → Plugin       | `mcp.invoke.tool`               |
| `mcp.{type}.response`                 | Plugin → Client       | `mcp.tool.response`             |
| `compositor::{event}`                 | Service → All Plugins | `compositor::workspace_changed` |

## JSON String Conversion

Generic widgets (e.g. `button`) that read topic/payload from config send plain JSON strings. The host converts these to typed messages using the
`JsonConverterRegistry`:

1. The widget sends an `FfiEnvelope` with `type_id = generate_type_id("std::string::String")`
2. The host's `try_convert_string_to_typed_envelope()` checks the registry
3. If a converter is registered for the topic, the string is deserialized to the typed struct
4. The converted envelope replaces the original

Model crates register their converters via `register_json_converters(context)`.

## Memory Management

- Payloads are allocated with `Box::into_raw(Box::new(payload))`
- `destroy_payload` is called by the host after all handlers process the message
- `clone_payload` is called when the broker duplicates an envelope for multiple recipients
- Use `default_destroy_payload` and `default_clone_payload::<T>` helper functions

See [Message Broker](../architecture/message-broker.md) for the broker architecture.
